# محاسبة بقالتي 1.5.6 — مشروع Android

هذه حزمة مصدر Android وليست APK. تضم واجهة المحاسبة محليًا داخل التطبيق، وتستخدم WebViewAssetLoader لتقديمها من أصل HTTPS محلي ثابت `appassets.androidplatform.net`؛ وهذا يعالج شرط secure context المطلوب لطلب الكاميرا في WebView. كما عولج طلب إذن الكاميرا وقت التشغيل، وأضيفت واجهة تصدير JSON إلى منتقي الحفظ واستيراد JSON عبر منتقي الملفات.

## الإعدادات
- الاسم: محاسبة بقالتي
- applicationId: `com.esmaeil.groceryapp`
- versionName: `1.5.6` — versionCode: `156`
- minSdk: 23 — compileSdk/targetSdk: 35
- البيانات محلية داخل WebView عبر LocalStorage وIndexedDB.
- لا يحتاج تشغيل الواجهة أو تسجيل العمليات إلى اتصال إنترنت؛ بعض ميزات جلب بيانات الباركود الخارجية تحتاج الإنترنت.

## البناء
يشمل المشروع GitHub Actions في `.github/workflows/build-apk.yml` لبناء APK تجريبي Debug ورفعه كـ artifact. الناتج ليس إصدارًا تجاريًا موقّعًا بمفتاح خاص.

## ما لم يتم التحقق منه بعد
لم يتوفر Android SDK أو Gradle في بيئة إعداد هذه الحزمة، كما أن الوصول الشبكي لتنزيلهما غير متاح؛ لذلك لم يُنفّذ بناء APK فعلي هنا ولم يجر اختبار على هاتف Android. يجب اختبار الحفظ بعد إغلاق التطبيق وإعادة فتحه، ووضع الطيران، والتصدير والاستيراد، والكاميرا على الهاتف قبل الاستخدام الفعلي. لا تعتمد على البرنامج كسجل وحيد قبل إجراء اختباراتك والاحتفاظ بنسخ احتياطية.

## ملاحظة وضع عدم الاتصال في نسخة Android
في تطبيق Android لا نحتاج إلى Service Worker؛ لأن ملف HTML مضمن داخل APK ويُحمّل من ملفات التطبيق المحلية. تم ضبط مؤشر الحالة ليميز هذه الحالة عن نسخة PWA التي تحتاج Service Worker. تبقى مزامنة بيانات الباركود الخارجية اختيارية وتتطلب الإنترنت، بينما إدخال الأصناف والحركات والحفظ المحلي لا يتطلبه.

## فحوصات المصدر المنفذة
- فحص بنية ZIP ووجود ملفات Gradle وManifest وواجهة التطبيق.
- فحص XML لملف AndroidManifest.
- فحص بناء الجملة لكتل JavaScript الثلاث داخل HTML باستخدام Node.js.
- فحص عدم تكرار معرّفات عناصر HTML.
- فحص اتصال زر النسخ الاحتياطي بجسر Android `exportBackup`.

هذه فحوصات ساكنة للمصدر وليست بديلًا عن تجميع Gradle أو اختبار APK على جهاز حقيقي.
